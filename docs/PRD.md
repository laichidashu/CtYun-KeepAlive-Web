## 一、原始需求复述

> "ctyun-auto 这个代码中有的功能整合进 CtYun-KeepAlive-Web-main 代码中，并完善 CtYun-KeepAlive-Web-main 功能"

**需求拆解**：

1. **整合**：把 ctyun-auto 中"宿主没有"的能力搬进 CtYun-KeepAlive-Web —— 即**积分任务（AI 对话 / 云电脑挂机）**、**自动兑换**、**定时调度（cron）**、**24 小时强制重启与进程守护**。
2. **完善**：补齐宿主的已知缺陷（配置丢失、日志抢占、无自愈、无 Web 配置项等），并把 Web 控制台从"单页账号管理"升级为"多面板运维控制台"。
3. **形态约束**：整合适配宿主的**单体 Web 应用 + AOT** 形态，而不是把 ctyun-auto 的 Docker+cron+Python 多进程架构照搬进来。Python 只作为**可选外挂执行器**存在。

## 二、现状与关键事实（本 PRD 的事实基线）

### 2.1 宿主项目（`CtYun-KeepAlive-Web`）

- 单进程 .NET 8 Web 应用，既跑保活客户端，又提供玻璃拟态 Web 管理台。
- 核心文件：`CtYun/Program.cs`（814 行，Minimal API + 保活编排）、`CtYun/CtYunApi.cs`（298 行，天翼云客户端 API，含 `ctg-signaturestr` 签名头）、`CtYun/Models/*`、`CtYun/Utility.cs`、`CtYun/wwwroot/index.html`（1215 行单页）。
- 现有 API：`POST /api/login`、`POST /api/change-password`、`GET /api/accounts`、`POST /api/accounts`、`POST /api/accounts/verify`、`POST /api/accounts/start`、`POST /api/accounts/stop`、`DELETE /api/accounts/{name}`、`GET /api/logs`（SSE）。
- 数据目录由环境变量 `CTYUN_DATA_DIR` 指定（Dockerfile 默认 `/app/data`），配置落 `accounts.json`。

### 2.2 被整合方（`ctyun-auto`）

- Docker 容器 + cron + Python(DrissionPage/Chromium/ddddocr)，外层 `entrypoint.sh` 守护 `dotnet CtYun.dll`。
- **AI 对话积分任务**：`app/login_script.py` → 走 CAS 登录 `eaichat.ctyun.cn`，随机发一条预设消息拿积分。cron `0 3,20 * * *`。
- **云电脑挂机积分任务 + 自动兑换**：`app/pc_login.py` → 登录 `pc.ctyun.cn`，进入 AI 云电脑挂机 80 分钟，期间轮询 `getTaskList` 的 `currentProgress`，≥3600 视为完成，完成后按 `redeem_config.json` 自动兑换。cron `0 4,6 * * *`。
- **进程守护**：`timeout 2m` 首次启动（触发短信）→ `timeout 24h` 常态运行 → 退出后 sleep 120 重启；兑换成功后写 `/tmp/ctyun_restart_at`（+120s）触发提前重启。
- 积分口径：每天约 300 积分；8c16g 配置需 300 积分；建议每月兑换一次长期维持 8c16g。

### 2.3 【重要新发现】两个 Python 脚本已在宿主仓库就位

经抽查确认（这一条改变了整合方案，请架构师特别注意）：

| 宿主路径 | 行数 | 对应 ctyun-auto 源文件 | 说明 |
| --- | --- | --- | --- |
| `CtYun-KeepAlive-Web/scripts/ai_chat_task.py` | 393 | `app/login_script.py`（393 行） | 内容一致，已重命名 |
| `CtYun-KeepAlive-Web/scripts/pc_hang_task.py` | 1238 | `app/pc_login.py`（1238 行） | 内容一致，已重命名 |

**脚本的既有调用契约（C# 侧必须遵守）**：

- 凭据通过**环境变量**注入：`APP_USER`、`APP_PASSWORD`；`RUNNING_IN_DOCKER=true` 时切换到容器路径与 headless 模式。
- `ai_chat_task.py` 无 CLI 参数；Cookie 持久化到 `/app/data/ctyun_cookies_{user}_.json`（非容器为 `./ctyun_cookies_{user}_.json`）。
- `pc_hang_task.py` 仅有一个 CLI 参数 `--config-redeem`；`authData` 持久化到 `/app/data/ctyun_authData_{user}_.json`。
- 退出码约定：`0` = 成功完成，`1` = 异常/超时/失败。
- 挂机总时长硬编码 `HANG_SECONDS = 80 * 60`；兑换后重启信号文件硬编码 `/tmp/ctyun_restart_at`。

**脚本的三个"非交互不可用"陷阱（决定架构的关键约束）**：

1. 兑换配置的创建走 `input()` 交互式问答；脚本第 799 行已有 `sys.stdin.isatty()` 检测，**非 TTY 时直接打印提示并返回 `{}`，不会挂死**——但结果是**静默跳过兑换**。
2. `ensure_redeem_config()` 的判断是 `if config and "enabled" in config: return config` —— **只要 `redeem_config.json` 存在且含 `enabled` 键，脚本就完全信任并直接使用，不再交互**。这是 C# 与脚本之间最关键的契约。
3. `--config-redeem` 独立模式在拿不到配置时 `sys.exit(1)`，**无法用于 Web 端"仅兑换"触发**。

**结论**：Web 端要驱动自动兑换，必须由 **C# 侧负责生成/维护 `redeem_config.json`**（满足上述契约），或由 C# 内置 HTTP 通道自行下单；不能指望脚本的交互式配置。

## 三、产品目标

1. **功能对等并超越**：把 ctyun-auto 的**积分任务、自动兑换、定时调度、24h 守护重启**四项能力整合进单体 Web 应用，且**不引入 Docker/cron 多进程依赖**——用户在宿主一套程序里即可获得原 ctyun-auto 的全部收益。
2. **可靠性达标**：消灭全部 P0 缺陷，让保活任务具备**自愈 + 退避重试 + 24h 强制重启**能力，做到"配好账号后可无人值守长期运行"，网络抖动/服务端异常不再导致账号永久躺平。
3. **可观测、可配置、可降级**：所有能力在 Web 控制台可见可配（定时任务、积分任务、兑换策略、保活参数），Python 相关能力在环境缺失时给出**明确可执行的降级提示**而非静默失败。

### 5.3 主线 C：定时任务调度器（SCHED）

> **架构建议（强约束）**：本机无 .NET SDK，**无法 `dotnet restore` / 编译验证第三方包**。因此**不要引入 Cronos/Quartz 等 NuGet 依赖**，请自研一个约 100–150 行的极简 5 段 cron 解析器，只支持：`*`、数字、`a-b`、`a,b`、`*/n` 五种语法，不支持秒、`?`/`L`/`W`/`H`。理由：零依赖 = 零 restore 风险 = 一次写对的概率最高。

### 5.5 主线 E：自动兑换（RDM）

> **关键契约（架构师必读）**：`pc_hang_task.py` 的 `ensure_redeem_config()` 判断为 `if config and "enabled" in config: return config`。因此 **C# 只要在正确路径写出含 `enabled` 键的合法 JSON，脚本就会完全信任并直接执行兑换，不再进入交互式问答**。
> 路径规则：容器内 `/app/redeem_config.json`；非容器 `./redeem_config.json`（**相对 Python 进程工作目录**，C# 调用时必须显式设置 `WorkingDirectory`）。
> 配置字段：`enabled`、`desktopId`(string)、`prodId`(int)、`prodName`(string)、`prodType`(string)、`costPoints`(int)、`maxRedeemTimes`(int，0 表示按积分尽量兑换)、`lastRedeemDate`(string，`YYYY-MM-DD`)、`scheduleType`(`daily`/`interval_days`/`monthly_days`)、`intervalDays`(int)、`monthlyDays`(list[int]，`-1` 表示月末最后一天)。

| NFR-1 | **AOT 兼容** | `PublishAot=true`。**禁止反射式序列化**；所有进/出 JSON 的类型必须在 `CtYun/Models/AppJsonSerializerContext.cs` 注册（`[JsonSerializable(typeof(...))]`）；禁止 `dynamic`、`MakeGenericType`、`Assembly.Load` 等运行时类型操作。本 PRD 新增的 DTO（任务、任务历史、设置、运行指标、兑换配置、奖励列表、环境自检结果）**全部需要注册**，请把清单列进架构设计的检查表。 |
| NFR-2 | **无 .NET SDK** | 本机无 `dotnet`，无法编译/restore。对策：① 不新增 NuGet 依赖（cron 解析器自研，见 SCHED 主线说明）；② 优先使用 BCL 内建 API；③ QA 以**严格代码评审**替代编译验证，评审重点：类型是否注册、null 安全性、async/await 死锁、Channel 与 CTS 生命周期、JSON 属性名大小写。 |

| NFR-4 | **可选能力降级** | Python/Chromium 缺失时，保活核心能力必须完全不受影响；积分/兑换功能必须在 UI 与日志两处给出**明确可执行的修复指引**，禁止静默失败。 |
| NFR-5 | **单进程不崩** | 积分任务子进程崩溃、Chromium 异常、脚本超时，均不得导致主进程退出或保活任务中断（异常隔离 + 任务级 try/catch）。 |

## 七、UI 设计稿说明（文字描述，不产出图形）

### 7.0 全局布局

沿用现有玻璃拟态（Glassmorphism）风格：深色渐变背景 + 半透明毛玻璃卡片 + 青/绿/红状态色。页面结构自上而下：

1. **顶栏**（固定）：左侧产品名与版本号；中部 **6 个 Tab 导航**（总览 / 账号 / 定时任务 / 兑换 / 日志 / 设置）；右侧"🔑 修改密码"、"🚪 退出"两个按钮（沿用现有 `btn-header` 样式）。
2. **内容区**：单面板全宽容器，Tab 切换时局部刷新，不整页跳转。
3. **登录遮罩**：沿用现有 `login()` 遮罩层，未认证时覆盖全部内容。

### 7.1 总览面板

- **顶部统计卡组**（横向 4–5 张卡）：账号总数 / 保活运行中数 / 今日积分任务（成功-失败）/ 下次任务触发时间 / 环境自检状态（✓ 或 ✗）。沿用现有统计卡视觉。
- **中部左栏"账号速览"**：紧凑列表，每行 = 状态徽标 + 备注名 + 手机号 + 运行时长 + 心跳成功/失败计数。
- **中部右栏"最近任务执行"**：最近 5 条执行历史（任务名、时间、耗时、成功/失败徽标）。
- **底部"系统提示"区**：环境自检不通过时，在此显示醒目告警条 + 修复命令（PTS-01）。

### 7.2 账号面板

- **顶部**：现有"添加账号"表单（含短信验证码两步流程，交互完全保留），右侧新增"🔄 刷新状态"按钮。
- **主体**：账号卡片网格（沿用现有卡片样式），每张卡包含：
  - 卡片头：备注名（大字）+ 手机号（小字灰）+ 右上角状态徽标（运行中[绿]/已停止[灰]/重试中[黄]/等待验证码[蓝]/环境不可用[红]）。
  - 运行指标行：本次启动时间 · 已运行 12h34m · 心跳 ✓1024 ✗3 · 连续失败 0 · 最后心跳 12:03:45 · 下次强制重启 11h26m 后。
  - 重试提示行（仅"重试中"显示）：`⚠ 连接失败，60 秒后自动重试（第 3 次）`。
  - 设备列表：每台设备一行，显示设备名 + 状态码 + 连接状态（连接就绪/连接出错/保活中）。
  - 操作按钮行：`⚡ 启动保活` / `🔴 停止保活` / `✏️ 编辑` / `🗑️ 删除`。
- **编辑弹窗**（新增）：备注名输入框、密码输入框、"保存"与"取消"。保存后提示"修改已保存；修改密码需重启保活后生效"。

### 7.3 定时任务面板

- **顶部工具条**：`➕ 新建任务` 按钮 + "调度器状态：运行中 · 下次检查 23 秒后" 文案。
- **任务列表**（表格）：列 = 任务名 / 类型（AI 对话 / 云电脑挂机）/ 关联账号 / Cron 表达式（附人类可读说明，如"每天 03:00 和 20:00"）/ 启用开关 / 上次执行 / 下次执行 / 状态 / 操作（立即执行 / 编辑 / 删除）。
- **新建/编辑弹窗**：任务名、类型下拉、关联账号下拉、Cron 表达式输入框（**下方实时显示人类可读描述与"下次 3 次触发时间"预览**，非法表达式实时红字提示）、超时（分钟）、启用开关。
- 表格下方为**执行历史**折叠区：最近 50 条，列 = 任务名 / 开始时间 / 耗时 / 退出码 / 结果徽标 / 日志摘要（点击展开）。

### 7.4 兑换面板

- **顶部状态条**：当前积分（若能获取）/ 上次兑换日期 / 下次可兑换判定结论（`兑换计划命中：已间隔 30 天，满足每月 1 号兑换` 或 `兑换计划未执行：距上次仅 3 天`）。
- **配置卡片**：
  - `启用自动兑换` 开关。
  - `目标设备`：下拉选择（来自账号已发现的 `desktopId`），手动输入兜底。
  - `兑换奖励`：下拉 + `🔄 拉取奖励列表` 按钮；选中后自动回填显示 `prodId` / `prodType` / `costPoints`。
  - `兑换次数上限`：数字输入，`0` 旁注"按积分尽量兑换"。
  - `时间策略`：单选组 —— 每天 / 每隔 N 天（N 输入框）/ 每月几号（逗号分隔输入，`-1` 表示月末）。
  - `保存配置` 按钮，保存后显示配置实际写入的文件路径。
- **通道说明区**（重要，降低用户误解）：一行说明"通道 A：C# 内置 HTTP（主）；通道 B：Python 挂机脚本（降级）。若 A 返回登录过期，请启用云电脑挂机任务以走通道 B。"并在通道 A 失败时在此显示红色错误。
- **兑换历史**：最近 20 条（时间 / 奖励 / 消耗积分 / 次数 / 结果码 / 消息）。

### 7.5 日志面板

- **工具条**：关键字过滤输入框 / 级别筛选（全部 / 成功 / 警告 / 错误）/ 自动滚动开关 / `📥 导出` / `清除`。
- **终端区**：沿用现有等宽字体 + 深色终端样式，按级别着色（信息白、成功绿、警告黄、错误红），每行前缀 `[HH:mm:ss.ff]`，来源标签 `[账号名]` 或 `[AI对话]` / `[挂机]` / `[系统]`。
- 断开 SSE 后自动重连，顶部显示"连接已断开，正在重连…"提示条。

### 7.6 设置面板

- 分区卡片：
  1. **安全**：修改管理密码（跳转现有弹窗）/ 会话有效期（小时）/ `立即登出所有会话`。
  2. **保活**：保活间隔（秒，30–3600）/ 24h 强制重启开关与周期（分钟）。
  3. **Python 环境**：Python 可执行文件路径 + `🔍 环境自检` 按钮 + 自检结果清单（Python 版本 / DrissionPage / ddddocr / requests / 脚本文件，每项 ✓ 或 ✗ 加修复命令）。
  4. **任务默认值**：AI 对话超时、挂机超时、错过触发补偿策略。
  5. **数据**：数据目录路径（只读展示）、`accounts.json` 路径、`导出诊断信息` 按钮。
